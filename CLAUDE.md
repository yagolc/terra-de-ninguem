# Terra de Ninguém

Jogo de estratégia medieval, assíncrono, no navegador, para um grupo fechado de até 8 amigos (entrada só por convite). Cada jogador evolui sua cidade em tempo real (produz mesmo offline) e disputa territórios num mapa compartilhado, com diplomacia no estilo War. Partidas em temporadas de 2 a 4 semanas, com objetivo secreto e reset do mapa.

Documentos de referência (leia antes de decisões de design):
- `docs/GDD.md`: design do jogo (recursos, prédios, unidades, combate, mapa, proteções, temporadas).
- `docs/plano-tecnico.md`: stack, modelo de dados, lógica do servidor, telas e ordem dos 8 épicos.

**Status:** Épicos 1 a 7 prontos (Fundação, Regras, Cidade, Mapa e temporada, Exército, Ataques, Objetivos e fim de temporada); próximo é o 8 (playtest e balanceamento). Temporadas de 3 semanas. Fila de até 3 obras e até 5 lotes de treino, independentes. Marchas a 20 léguas/h (cavalaria 40): vizinhos em ~20–30 min. Temporada 4 ativa desde 10/11/2026 (semente-base 6363, mapa para 8 jogadores; termina em 01/12). Use uma semente nova a cada temporada: a mesma semente repete o mapa. Épico 1: Projeto Supabase `wbhcmkortcklhcojphlx` (região São Paulo, plano Free) ligado à CLI; migration 0001 e a função `resgatar-convite` publicadas; e-mails em português saindo por SMTP do Gmail. Frontend publicado na Vercel em https://terra-de-ninguem.vercel.app (Root Directory `apps/web`, republica a cada push na `main` de github.com/yagolc/terra-de-ninguem; variáveis `VITE_*` configuradas no painel da Vercel).

## Pilares que guiam decisões

1. Estratégia acima da sorte: aleatoriedade de no máximo ±10% numa batalha.
2. Tensão sem frustração: ninguém perde tudo de uma vez (saque máx. 30%, escudo, proteção de iniciante, cidade principal nunca é conquistada).
3. Escolhas com custo: cada habitante é trabalhador ou soldado, nunca os dois.
4. A diplomacia é o jogo.
5. Sessões curtas: 5 a 10 minutos já rendem progresso.

## Stack

## Estrutura

```
apps/web/            # frontend React (telas em src/telas, cliente Supabase em src/lib)
packages/regras/     # @terra/regras: fórmulas puras de produção, custos e batalha
supabase/
  migrations/        # SQL numerado: tabelas, RLS, jobs pg_cron
  functions/         # Edge Functions, uma pasta por comando (kebab-case)
docs/                # GDD e plano técnico
```

Monorepo com **npm workspaces** (não usar pnpm/yarn).

## Comandos

```bash
npm install          # na raiz, instala tudo
npm run dev          # frontend em http://localhost:5173
npm test             # Vitest em todos os pacotes
npm run typecheck    # tsc em todos os pacotes
npm run build        # build de produção
npm run temporada:nova -- --semente 1234 --jogadores 6
                     # gera mapa + prévia em supabase/.temp/previa-temporada.svg; com --aplicar encerra a
                     # temporada ativa e grava a nova (uma transação). Vagas iniciais sem dono ficam para quem chegar depois; sem vaga livre, a temporada está cheia e o `entrar` recusa.
npm run simular -- --atacante 50l,20a,10c --defensor 40l,30a --terreno floresta --muralha 3
                     # simula 1000 batalhas (l/a/c = lanceiro/arqueiro/cavalaria; --cidade, --estoque, --armazem)
npm run arte         # converte docs/arte/originais em WebP para o site (precisa do ffmpeg)

# Supabase (CLI já logada e ligada ao projeto; rode na raiz)
npx supabase db push --linked                                  # aplica migrations novas
npx supabase functions deploy <nome>                           # publica uma Edge Function
npx supabase config push                                       # aplica supabase/config.toml (Auth etc.) no projeto
npx supabase db query --linked "select public.gerar_convite('amigo@email.com');"  # cria convite
npx supabase db advisors --linked                              # checagem de segurança/RLS
```

`supabase/config.toml` é a fonte da verdade das configurações do projeto (cadastro público desligado, URLs de redirecionamento). Mude ali e rode `config push`, não no painel; confira o diff antes de confirmar.

**Login:** "Entrar com Google" é o principal; código de 8 dígitos por e-mail (`{{ .Token }}` nos modelos, `verifyOtp`) é a alternativa para quem não usa Google, e funciona mesmo lendo o e-mail em outro aparelho. Cadastro público continua desligado: o convite (`resgatar-convite`, `metodo: 'google'`) cria a conta já confirmada sem e-mail, e o primeiro login Google com o mesmo endereço é ligado a ela automaticamente (testado). Cliente OAuth no Google Cloud (projeto "Terra de Ninguem", app publicado) com redirect `https://wbhcmkortcklhcojphlx.supabase.co/auth/v1/callback`.

Exceção: o SMTP (Gmail pessoal com senha de app) e o provedor Google (Client ID/Secret) são configurados **só no painel** (Authentication → Emails → SMTP Settings), porque tem senha. Mantenha `[auth.email.smtp]` comentado e não crie `[auth.external.google]` no `config.toml`, para o `config push` não mexer neles. Os modelos de e-mail ficam em `supabase/templates/` e só podem ser alterados com SMTP próprio ativo.

## Como um comando funciona (padrão do Épico 3)

- **Edge Function** (`supabase/functions/<nome>/index.ts`) importa as regras direto de `../../../packages/regras/src/index.ts`; o deploy leva os arquivos junto. Código comum fica em `supabase/functions/_compartilhado/` (`auth.ts` valida o token com `getUser`, `db.ts` conecta direto ao Postgres via `SUPABASE_DB_URL`, `http.ts` tem CORS e `ErroDoJogo`).
- Funções publicadas com `--no-verify-jwt` e `verify_jwt = false` no `config.toml`: o token é validado no código.
- Cada comando: `sql.begin` → `select ... for update` na cidade e nas tropas do jogador → `avancarCidade` até agora (conclui obras e lotes de treino em ordem, consumo de comida e deserção) → valida com `verificar*` das regras → grava cidade, tropas (`distribuirPerdas` entre territórios), `obras` e `filas_treino`. Recusas lançam `ErroDoJogo(MENSAGENS_*[motivo])`.
- Obras e lotes concluídos são gravados no próximo comando do jogador ou pelo agendador (a cada minuto, `atualizarPlacar` avança e salva todas as cidades). O navegador já os mostra antes porque calcula com `avancarCidade`; o mapa soma os lotes prontos ao território da cidade.
- Sem Deno local: para checar tipos das Edge Functions, rode `tsc` com `paths` apontando `npm:postgres@3.4.5` e `jsr:@supabase/supabase-js@2` para os pacotes do npm.
- O gerador de mapa (`@terra/regras/mapa`, usa `d3-delaunay`) fica **fora** do `index.ts` das regras: só o script de temporada e testes o importam; Edge Functions e site leem o mapa pronto do banco. Desde a temporada 4: 6 territórios por jogador, cidades iniciais só na borda (`territoriosNaBorda`) e rios/cordilheiras (`escolherBarreiras`, `BALANCEAMENTO.mapa.barreiras`): a barreira sai de `fronteiras` (as regras nem a veem) e vai para a tabela `barreiras` (migration 0022), só para o mapa desenhar.
- `territorios.guarnicao_inicial` (força dos bárbaros) não tem `grant select`: liste as colunas no `select` do cliente, nunca `*`.
- **Ataques (Épico 6):** `enviar_marcha` (função `cidade`) tira as tropas do território e cria a marcha. O pg_cron (migration 0007) chama `resolver-marchas` a cada minuto com o cabeçalho `x-segredo-cron`: a senha fica no Vault (`segredo_cron`) e na variável `SEGREDO_CRON` da função (`npx supabase secrets set`), nunca no git. Cada marcha é resolvida numa transação (`for update skip locked`), travando as cidades por ordem de id; sorte = `sementeDeTexto(marcha.id)`. Marcha tipo `movimento` leva tropas entre territórios próprios ligados por territórios próprios (sem batalha; se o destino cair no caminho, desde a temporada 4 as tropas lutam para retomá-lo: `resolverAtaque` com tipo `conquista` e `retomada: true` nos `dados` do relatório, sem quebrar o escudo de quem mandou; se o destino virou cidade principal de alguém, vão para a cidade). Perdedor perde 70%; conquista exige 1,5×; o defensor derrotado recua para a cidade dele e ganha escudo de 8 h; atacar quebra o próprio escudo. A proteção de iniciante vale também na chegada: se o alvo virou de um jogador enquanto a marcha andava, as tropas voltam sem batalha, com um relatório `devolvida` (migration 0021: sem vencedor, só o atacante vê, não conta como vitória). O escudo só barra o envio; marchas que já estavam a caminho lutam.
- **Objetivos (Épico 7):** sorteados em `garantirObjetivo` quando o jogador entra (ação `entrar`), com semente da temporada + jogador; secretos pelo RLS até a temporada encerrar. A cada minuto, depois das marchas, `atualizarPlacar` recalcula o `placar` (público), confere os objetivos e encerra a temporada (objetivo cumprido, monopólio comercial, ou prazo → mais pontos; `motivo_fim` = `objetivo`/`monopolio`/`prazo`). Encerrada, os comandos param (`temporadaAtiva` recusa) e o site mostra a tela de fim até você rodar `temporada:nova`.
- **Segurar o objetivo (migration 0026):** cumprir não encerra na hora. `relogioDoObjetivo` (regras) liga o relógio quando o objetivo passa a valer e vence depois de `objetivos.segurarHoras` seguidas (não corre na proteção de iniciante); `atualizarPlacar` guarda o início em `placar.objetivo_desde` (público: o mapa e a tela Objetivo mostram quem e quando, nunca o tipo), apaga o escudo de quem está segurando e encerra os pactos de não agressão dele (`pacto_ate = agora`), o `resolver-marchas` não dá escudo a ele e `responder_pacto` recusa aceitar não agressão com quem está segurando (`objetivo_em_jogo`). "Fronteiras de ferro" sorteado desde a temporada 5 pede também `muralha` (nível máximo, `SituacaoJogador.nivelMuralha`); cartas sem `muralha` valem como antes.
- **Monopólio comercial (migration 0017):** não é mais objetivo secreto; é a vitória aberta a todos. `monopolioComercial` (regras) diz quem tem todas as cidades livres e quando vence (`objetivos.monopolioHoras` depois da última tomada); `atualizarPlacar` encerra a temporada com `motivo_fim = 'monopolio'`, e o mapa e a tela Objetivo mostram o relógio para todos. Carta antiga de `monopolio_comercial` é trocada por outra sorteada (`sortearPara`) no próximo `atualizarPlacar`.
- **Tipos de objetivo:** duas regiões, metade do mapa, fronteiras de ferro, derrubar rival, senhor das vilas (metade das vilas do mapa no nível 3, `metaSenhorDasVilas`; substitui população, que não é mais sorteada), senhor da guerra (vitórias contra jogadores), mestre construtor (prédios no nível máximo) e tesouro (ouro que só cabe no Armazém máximo). Desde a temporada 5 o sorteio olha a cidade (`sortearPara` passa `vizinhancaDaCidade` e `racasVizinhas`): duas regiões = a da cidade + uma vizinha que comece a `objetivos.vizinhaDistanciaMinima` fronteiras e tenha outra cidade inicial (`outrasCidades`: vagas iniciais e cidades fundadas; senão qualquer vizinha, senão a dupla mais perto); velha rixa só mira raças de jogadores com cidade a até `objetivos.rixaDistanciaMaxima` fronteiras. Servidor (`atualizarPlacar`) e site (`useTemporada`) montam a mesma `SituacaoJogador`; um teste confere que as metas cabem nos limites do jogo.
- Código de cidade compartilhado em `_compartilhado/cidade.ts` (`carregarCidade` → `avancarAteAgora` → mexe → `salvarCidade`). Tropas em marcha comem e ocupam população, mas não desertam.
- Para conferir o agendador: `select status_code, content from net._http_response order by created desc limit 5`. Para testar sem esperar: `update marchas set chegada_em = now() where id = ...` (só em teste).
- **Reconhecimento:** `enviar_reconhecimento` (função `cidade`) custa ouro e manda um batedor (marcha `reconhecimento`, sem tropas) a um vizinho; ao chegar, `resolver-marchas` grava em `reconhecimentos` as tropas de qualquer dono, o terreno e a muralha, com `disponivel_em` = volta do batedor (o RLS só mostra depois disso). A web mostra no painel do território e em Relatórios, com `analisarDefesa` (quantas unidades de cada tipo conquistam mesmo com azar máximo).
- **Estruturas (migration 0011):** `construir_estrutura` (função `cidade`) põe uma torre, paliçada ou entreposto num território do jogador (uma por território, custo em comida e ouro em `BALANCEAMENTO.estruturas`, sem fila). As alheias são secretas (migration 0012): o RLS de `estruturas` só mostra as próprias e o mapa usa `estruturas_no_mapa(p_temporada)`, que devolve tipo e prazo nulos nas dos outros (❓); o batedor grava `estrutura`/`estrutura_pronta` em `reconhecimentos`. A conquista apaga a estrutura do território (`resolver-marchas`). Paliçada entra em `resolverBatalha`/`analisarDefesa`; entreposto em `bonusDeTerritorios`. A torre usa a função `marchas_vistas_pela_torre()` (security definer): devolve só marchas alheias para territórios do jogador com torre pronta, com o total de soldados; as marchas continuam secretas no RLS. O site relê o mapa a cada minuto e mostra ⚠️ na aba Mapa.
- **Acampamento militar e destruir estrutura (migration 0029):** `acampamento` é a 4ª estrutura (`BALANCEAMENTO.estruturas.acampamento`, limite em `acampamento.maximoPorJogador`; `verificarEstrutura` recusa na cidade principal e acima do limite). `filas_treino.territorio_id` (nulo = cidade): `treinar_tropas` aceita `territorio_id` do acampamento pronto do jogador (`verificarTreino` com `noAcampamento`), e `avancarAteAgora` põe o lote concluído lá se o território ainda é dele (senão na cidade); o mapa (`useMapa`) soma igual. `destruir_estrutura` (função `cidade`, `verificarDestruicaoEstrutura`) apaga a estrutura sem devolver nada; destruir acampamento, e a conquista no `resolver-marchas`/hordas, zeram o `territorio_id` dos lotes. No site: escolha "Ficam prontos em" no `PainelQuartel`, `DestruirEstrutura` no painel do território, ⛺ no mapa.
- **Estradas (migration 0018):** tabela `estradas` à parte das estruturas (um território pode ter as duas), pública no RLS. `construir_estrada` (função `cidade`, regras `verificarEstrada`, custo em `BALANCEAMENTO.estrada`); no movimento, `multiplicadorEstrada` (estrada pronta na saída e na chegada) entra em `duracaoMarchaMs`. Ataques não usam. `resolver-marchas` apaga a estrada na conquista. O mapa desenha o caminho entre vizinhos com estrada; `PainelEstrada` no painel do território.
- **Hordas bárbaras (migration 0020):** regras em `hordas.ts` (`proximaHordaEm`, `exercitoDaHorda`, `recompensaDaHorda`, `escolherAlvoDaHorda` entre os `hordas.primeirosDoPlacar`, `origemDaHorda`). `resolver-marchas/hordas.ts` (`cuidarDasHordas`, a cada minuto, antes do placar) resolve as que chegaram (`resolverBatalha` contra o dono; ouro, saque da cidade ou território neutro com a horda de guarda) e solta a próxima. Tabela `hordas` pública (sem o exército do defensor). O site lê em `lib/hordas.ts`: seta vinho e ☠️ no mapa, aviso no alto da tela Mapa (a que vem ou o fim da última, por 12 h) e, em Relatórios, as que atacaram o jogador.
- **Cancelar obra ou treino:** `cancelamento.ts` (regras): `cancelarObra` tira a obra e as de depois que dependem dela (mesmo prédio, ou acima do Centro que sobrou), `cancelarTreino` tira o lote; os dois devolvem 100% do custo e adiantam a fila (duração = distância até o fim do anterior). Função `cidade`: `cancelar_obra`/`cancelar_treino` com `pronto_em` do item; `salvarCidade` grava os horários que mudaram. No site, o ✕ do item abre `JanelaConfirmacao` (`<dialog>`) com o que sai e o que volta.
- **Missões de início (migration 0019):** `missoes.ts` (regras) lista `TIPOS_MISSAO`, a condição de cada uma sobre `SituacaoMissoes` e `verificarResgateMissao` (recompensa em `BALANCEAMENTO.missoes`, limitada ao armazém). `cidades.missoes` guarda as resgatadas; a ação `resgatar_missao` (função `cidade`) confere e grava. O site monta a mesma situação em `useCidade` e mostra `PainelMissoes` ("Primeiros passos") no alto da tela Cidade até todas serem pegas.
- **Povoados (migration 0013):** o gerador (`escolherCidadesLivres`, `escolherVilas`) põe vilas e cidades livres em `MapaGerado.povoados`; o `temporada:nova` grava em `povoados` (público, só leitura). O dono é o do território. Regras em `povoados.ts`: estoque da vila neutra pelo tempo (`saqueada_em`), saque da vila neutra ou de jogador (zera o nível), níveis da vila (`melhorar_vila` na função `cidade`), lealdade (`leal_desde`) e `bonusDosPovoados` (população extra e ouro fixo), que entram em `avancarCidade` no servidor (`carregarCidade`) e no site (`useCidade`). `resolver-marchas` aplica a muralha da cidade livre, o saque de vila e, na conquista, a posse, a lealdade e a milícia (`povoados.milicia`, migration 0014: lanceiros que defendem a cidade livre fora da população e das tropas do jogador; o batedor os conta). O monopólio comercial usa `posse_desde`.
- **Heróis (migration 0015):** `herois` (só o dono lê) guarda nome, especialidade, nível, onde está (`territorio_id` ou `marcha_id`), `treino_pronto_em` e `ferido_ate`; `marchas.heroi_id` e `reconhecimentos.heroi`. Regras em `herois.ts` (bônus por nível de cada especialidade em `herois.bonusPorNivel`, `bonusHeroi(nivel, especialidade)`, treino, `heroiDisponivel`, `bonusIntendente`); batalha (`bonusAtaque`/`bonusDefesa`), `duracaoMarchaMs` (velocidade), `capacidadeCarga` (carga) e `avancarCidade` (`bonusCrescimento`) aceitam o bônus. `carregarCidade` trava o herói e soma o intendente; `soldados(c)` conta o herói. Função `cidade`: `recrutar_heroi`, `treinar_heroi` e `com_heroi` em `enviar_marcha`. `resolver-marchas` move o herói (`_compartilhado/herois.ts`): conquista fica, vitória volta com as tropas, derrota fica ferido na cidade.
- **Raças e herdeiro (migration 0016):** `cidades.raca` (escolhida em `entrar`, que agora exige `raca` e aceita `nome`; o site mostra a crônica de `lib/cronicas.ts` e a tela `Fundacao` antes) e `cidades.guarda_real`. A raça dos outros é lida por `racas_na_temporada(p_temporada)` (security definer, só jogador e raça). Efeitos em `BALANCEAMENTO.racas`/`racas.ts`, somados ao herói em produção, crescimento, batalha (`bonusDefesaRaca` depende do terreno), velocidade e carga. Herdeiro = vencedor da última temporada encerrada (`herdeiroDoTrono`): ganha a Guarda Real ao fundar (defende como a milícia) e vale `herdeiro.pontosPorVitoria` a mais no placar. O objetivo "velha rixa" conta territórios distintos conquistados de jogadores da raça (substitui "derrubar rival", que não é mais sorteado). Cada temporada nova ganha um capítulo em `CRONICAS`.
- **Perfil (migration 0023):** `jogadores` ganhou `cor_secundaria`, `padrao`, `emblema` (jsonb, até 20 camadas de formas, migration 0024; `emblema.ts` das regras, `verificarEmblema`) e `descricao` (públicos; valores válidos em `perfil.ts` das regras, `verificarPerfil`: cor principal da paleta e sem repetir a de outro jogador com cidade na temporada ativa). Nome em `nome.ts` (`verificarNomeJogador`, comparação por `chaveDoNome`, sem maiúsculas nem acentos). Função `cidade`, ação `salvar_perfil` (`_compartilhado/perfil.ts`, com ou sem temporada ativa); a fundação usa o mesmo `gravarNomeJogador`. Estatísticas pela função `perfil_jogador(p_jogador)` (security definer): temporadas com raça e colocação no placar, e rivalidades só de temporadas **encerradas** (as da ativa revelariam quem guerreia com quem). No site: tela `Perfil` (aba `perfil`, `#perfil` ou `#perfil=<id>`), aberta pelo nome no cabeçalho e pelos nomes do placar; `Bandeira` (SVG) e `lib/bandeira.ts` (formas dos padrões); no mapa, a bandeira inteira vira imagem pelo SVG de `lib/svgBandeira.ts` (`svgDaBandeira`, textura do Phaser por `chaveDaBandeira`, carregada uma vez); `EditorEmblema` (arrastar no quadro, camadas, tamanho, largura e altura, rotação, cor, espelho, formas e emblemas prontos), com o desenho das formas em `lib/formasEmblema.ts` (caminhos SVG de -50 a 50). O `temporada:nova` mantém a cor de cada um e só troca se repetir.
- **Pombos e pactos (migration 0025):** prédio `pombal` (até o nível 5) e tabela `cartas` (RLS: quem mandou lê sempre; quem recebe, só depois de `chega_em`). Regras em `pombos.ts` (`pombosDoPombal`, `duracaoVooMs` da cidade de um à do outro, `verificarCarta`, `verificarRespostaPacto`, `pactoEntre`; números em `BALANCEAMENTO.pombos`). Função `cidade`: `enviar_carta` (texto e/ou `proposta: 'nao_agressao'` com `horas_pacto` de 1 a 12), `responder_pacto` (aceita grava `pacto_ate`) e `marcar_cartas_lidas`. Pacto em vigor (`_compartilhado/pombos.ts`, `fimDoPacto`) barra o envio de ataque (`verificarAtaque`, motivo `pacto_nao_agressao`) e, na chegada, `resolver-marchas` devolve a marcha com relatório `devolvida` (`motivo: 'pacto'`). Pactos são secretos e não se rompem. **Acesso militar** (migration 0027): `proposta: 'acesso_militar'`, mesmas colunas (`pacto_ate`); `fimDoPacto` só olha `nao_agressao`. `terrasParaMarchar` (`_compartilhado/pombos.ts`, e `lib/corredor.ts` no site, que lê `acessosMilitares` do `useMapa`) monta o corredor (terras dos parceiros, menos as do dono do alvo); movimento usa `ligadosPorTerritoriosProprios` com `corredor`, ataque e batedor usam `alcancaOAlvo` (regras) no lugar da fronteira direta. No site: aba `cartas` (`#cartas` ou `#cartas=<id>`, botão no perfil), `useCartas`, `FormularioCarta`, `ItemCarta`, aviso de não lidas na aba.

## Regras de arquitetura (não quebrar)

- **Servidor autoritativo.** O cliente só mostra estado e envia comandos para Edge Functions. Ele nunca dá `insert`/`update` direto em tabelas de jogo; as políticas RLS não devem permitir isso.
- **Regras puras.** `packages/regras` não acessa banco, rede, relógio nem `Math.random` direto: recebe números (incluindo o instante atual e a semente/valor aleatório) e devolve números. É usado pelo servidor e pelo cliente para calcularem igual.
- **Produção por tempo decorrido.** Nada roda a cada segundo. Antes de qualquer comando, o servidor atualiza a cidade a partir de `atualizado_em`.
- **Comandos em transação** com trava na linha da cidade (`select ... for update`) para evitar gasto duplo.
- **RLS em toda tabela**, sem exceção. Segredos (objetivos, tropas e marchas alheias) nunca são legíveis por outros jogadores.
- **Balanceamento num único arquivo** de configuração em `packages/regras` (custos, tempos, produção). Nada de número mágico espalhado.
- **Quase tudo pertence a uma temporada.** Só `jogadores` atravessa temporadas.

## Convenções

- **Idioma do domínio: português**, sem acentos em identificadores: tabelas, colunas, tipos e funções do jogo (`cidades`, `atualizado_em`, `construirPredio`, `construir_predio`). Termos técnicos genéricos podem ficar em inglês (`useSession`, `props`).
- SQL em `snake_case`; TypeScript em `camelCase` para variáveis/funções e `PascalCase` para tipos e componentes.
- Migrations: `supabase/migrations/NNNN_descricao.sql`, nunca editar uma migration já aplicada; crie outra.
- TypeScript `strict` com `noUncheckedIndexedAccess`. Sem `any`.
- Componentes React em função, um por arquivo; telas em `src/telas/`.
- UI responsiva, mobile first: no celular, barra inferior (Cidade, Mapa, Relatórios); no desktop, mapa no centro e painéis ao lado.
- Toda fórmula nova em `packages/regras` vem com teste Vitest; para limites do GDD (sorte ±10%, saque ≤ 30%, perdas válidas), teste também com centenas de casos gerados por `geradorComSemente`.
- Em `packages/regras`, imports relativos levam a extensão `.ts` (`from './batalha.ts'`) e só sintaxe apagável (sem `enum`/`namespace`): o mesmo código roda no Vite, no Deno (Edge Functions) e no Node 24 (simulador) sem build.
- Tempos nas regras são timestamps em ms; taxas no balanceamento são "por hora". Validações devolvem `{ ok: true, ... } | { ok: false, motivo }` com motivos em `snake_case`, que o servidor traduz para a mensagem do jogador.
- Textos da interface em português do Brasil.
- Variáveis de ambiente do frontend com prefixo `VITE_`; chaves secretas (service role) só nas Edge Functions, nunca no frontend nem no git.
